# 06 · 贴图窗口

> Snipaste 的核心洞察：**贴图不是"复制到剪贴板的图片"，而是一个置顶的、可操作的图片窗口。**
> 复刻它的时候，最容易做错的是三种消失方式的语义，所以本文把它们钉死。

## 1. 三个动作，三种语义

| 动作 | 键 | 窗口 | 能否恢复 | 影响"可恢复计数" |
| --- | --- | --- | --- | --- |
| **关闭** | `Esc` / 双击 / `Ctrl+W` | 消失 | ✅ 再按贴图键可恢复（最多 N 张，默认 1） | 占用 |
| **隐藏全部** | `Shift+F3` | 全部隐藏 | ✅ 再按一次全部回来 | 不占用 |
| **销毁** | `Shift+Esc` / 右键菜单 | 消失 | ❌ 永久 | 释放 |

实现上：

```rust
enum PinState {
    Visible,
    Hidden,                  // 隐藏全部留下的
    Closed { at: u64 },      // 关闭，进 recoverable 队列
    Destroyed,               // 不可恢复
}
```

- `recoverable` 是一个有界队列（长度 = `closed_history` 配置，默认 1）。
  超出时最旧的被**销毁**（并释放内存）。
- 退出应用时：`Closed` 且未显示的贴图**全部销毁**（与 Snipaste 一致，避免下次启动
  冒出一堆"幽灵图"）；`Hidden` 的保留（用户明确说过"暂时"）。
- 「销毁后按贴图键还能贴出来」不是 bug：那是剪贴板里还有内容，被当成**新**贴图。
  这一点在 UI 文案里要说清楚，否则永远有人来问。

## 2. 窗口属性

| 属性 | 值 | 说明 |
| --- | --- | --- |
| 边框 | 无（`decorations: false`） | 拖动靠自绘区域 |
| 置顶 | 是（`alwaysOnTop`） | 可在右键菜单临时取消（P2） |
| 焦点 | 不抢（`focus: false`） | 贴图不该打断你正在打的字 |
| 阴影 | 可选（默认开） | 用窗口阴影，不画在内容里 |
| 透明度 | 10%–100%，整窗 | `Ctrl`+滚轮 / `Ctrl`+`+`/`-` |
| 鼠标穿透 | 按贴图单独开关 | 全局热键切换光标下那张 |
| 多屏 | 记住所在显示器，屏幕拔掉时迁回主屏 | 防止"贴图跑到不存在的屏幕" |

`focus: false` 的例外：按 `空格` 打开标注工具条时临时获得焦点，`Esc` 后释放。

## 3. 剪贴板 → 贴图

按优先级尝试（与 Snipaste 一致）：

1. **图像**：`public.tiff` / `image/png` / `CF_DIB` → 贴图；
2. **文件路径**：若全部是图片 → 按图片贴；否则贴文本（可配置为始终贴路径文本）；
3. **颜色**：`#RRGGBB`、`255, 128, 0`、`1.0, 0.5, 0.0` → 生成 64×64 色块 + 色值文字；
4. **纯文本 / HTML**：用当前渲染字体排版成图（自动换行，最大宽度 800 px，
   超过 4000 字符截断并提示）；
5. **空剪贴板**：无声失败 + 托盘气泡「剪贴板里没有可贴的内容」。

文本贴图保留原文（`Ctrl+Shift+C` 可复制回纯文本），不是"截图化的文字"。

## 4. 交互

| 操作 | 行为 |
| --- | --- |
| 拖动 | 左键拖，贴边时吸附到其他贴图/屏幕边缘（±8 px） |
| 缩放 | 滚轮（±10%）、`+`/`-`（±10%）、拖四边/四角 |
| 旋转 | `1` 顺时针 90°、`2` 逆时针 90°（内容重绘，不是窗口旋转） |
| 翻转 | `3` 水平、`4` 垂直 |
| 复位 | 中键单击 → 100% 尺寸 + 100% 不透明 |
| 缩略图 | `Shift`+双击 → 缩到 180 px 宽，再按恢复 |
| 放大镜 | 按住 `Alt`，与截图态同一实现 |
| 取色 | 放大镜可见时 `C` |
| 右键菜单 | 复制 / 另存为 / 贴到剪贴板 / 透明度 / 分组 / 关闭 / 销毁 |
| 分组 | 右键 → 移到分组；关闭分组 = 批量关闭其成员 |

## 5. 多窗口管理

- 每张贴图 = 一个独立 Tauri 窗口（label `pin-<id>`），懒创建、关闭时销毁窗口对象
  但保留数据（可恢复）。
- 全量操作走一个 `PinManager`：
  ```rust
  struct PinManager {
      pins: HashMap<PinId, Pin>,
      groups: BTreeMap<String, Vec<PinId>>,
      recoverable: VecDeque<PinId>,
      hidden: bool,
  }
  ```
- 20 张 4K 贴图 = 20 × 33 MB 位图 ≈ 660 MB，太高。因此：
  - 内存里只保留**缩略图**（长边 ≤ 1024）与原始 blob 的路径；
  - 窗口绘制时按需从 blob 解码，`visible_pins` 变化时用 LRU 淘汰；
  - 实测目标：20 张 4K 贴图常驻内存 ≤ 300 MB。
- 全局热键 `Shift+F3` 切换隐藏：只改窗口可见性，不销毁。

## 6. 渲染细节

- 贴图内容用 `<img>`（浏览器原生缩放）而不是 canvas：原生缩放会用高质量的
  Lanczos 路径，且省掉一层 JS 合成。
- 缩放时设置 `image-rendering: auto`；对**纯文字**贴图提供「关闭平滑缩放」选项
  （`pixelated`），这是 Snipaste 用户常提的需求 —— 100% 以上放大时文字更锐。
- 旋转 90° 用 CSS transform + 尺寸互换，避免重采样损失；连续四次旋转回到原图。

## 7. 性能预算

| 场景 | 预算 |
| --- | --- |
| 从剪贴板到贴图可见 | ≤ 120 ms（4K 图） |
| 拖动/缩放帧率 | 60 fps（4K 图，缩放中允许降采样预览） |
| 20 张贴图常驻内存 | ≤ 300 MB |
| 隐藏/显示全部 | ≤ 50 ms |

## 8. 测试

- 语义测试：`关闭 → 贴图键恢复`、`关闭超过 N 张 → 最早的消失`、`销毁 → 不可恢复`、
  `退出时 Closed 被销毁而 Hidden 保留`。这些是纯状态机测试，不需要真窗口。
- 剪贴板解析：五类内容各一个 fixture，断言解析结果的类型与优先级。
- 拖拽吸附：给定窗口矩形集合，断言吸附后的坐标。
