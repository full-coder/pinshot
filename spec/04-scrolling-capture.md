# 04 · 滚动截屏（核心模块）

> 这是本产品唯一「做不好就等于没做」的模块，因此它先于 UI 完成，并且是可单测的纯函数。
> 实现见 `crates/pinshot-stitch/`。

## 1. 为什么不简单

「把滚动过程中的截图拼起来」听起来像调 API，实际有七个坑：

1. **粘性页眉**：每一帧顶部都有同一条导航栏，直接拼会在长图里重复 N 次。
2. **固定侧边栏 / 悬浮客服按钮**：它们不随内容滚动，会污染位移估计。
3. **滚动位置不确定**：浏览器可能按像素滚、按行滚、带惯性、还有 `scroll-behavior: smooth`。
4. **懒加载**：图片在滚到视口内之后才出现，抓早了就是一块空白。
5. **动画与视频**：帧间差异巨大，相关性骤降。
6. **亮度/色彩漂移**：渐隐动画、半透明遮罩、HDR 转换都会改变像素值。
7. **自动滚动注入被拦**：某些页面（地图、canvas 应用、远程桌面）不响应合成滚轮事件。

所以算法必须**先判断「哪些像素可信」，再算位移**，而不是全图求差。

## 2. 三种模式

| 模式 | 谁在滚 | 适用 | 实现 |
| --- | --- | --- | --- |
| 自动 | 程序注入滚轮事件 | 网页、文档、列表（80% 场景） | `ScrollInjector` + 稳定检测 |
| 手动 | 用户滚动 | 地图、远程桌面、注入被拦、手感要求高 | 连续抓帧循环，不注入事件 |
| 窗口级 | 程序注入 + 按窗口抓帧 | 目标窗口被别的窗口遮挡 | SCK `desktopIndependentWindow` / WGC `CreateForWindow` |

自动模式失败时**必须**自动降级到手动模式，并提示「已切换手动滚动，请自行滚动页面」。

## 3. 状态机

```
Ready
  │ 用户点「滚动截屏」/ 拖选区到底部出现提示后按 S
  ▼
Locating ── 找到滚动容器 → 把选区裁剪到容器内部
  │ 找不到（非标准应用）
  ▼
Capturing ◀──────────────┐
  │ 抓一帧 F_k            │ 等待 settle_ms
  ▼                       │
Scrolling ── 注入一次滚动 ─┘
  │   │
  │   └─ 连续 2 帧无位移 → Finishing
  ▼
Stitching ── 置信度不足 → Degraded（提示接缝 / 转手动）
  │
  ▼
Done（长图进入 Annotation 状态）
```

任一状态 `Esc` → 取消，已抓的帧保留在临时目录（用户仍可手动选）。

## 4. 定位滚动容器

优先级从高到低：

1. **辅助功能树**：`AXUIElementCopyElementAtPosition` → 向上找 `AXScrollArea` /
   `AXWebArea`，取其 `AXFrame`；Windows 用 UIA `ScrollPattern`。
2. **探测式**：在选区中心注入一次 1 像素滚轮，比较前后两帧的差异区域，
   差异最大的连通矩形即容器内容区（能处理 Electron / 游戏 UI）。
3. **兜底**：整个选区。

容器确定后，把选区裁剪到容器内，并记录容器内边距（`scroll_padding`），因为
粘性页眉通常叠在容器顶部之上。

## 5. 自动滚动的注入

| 平台 | API | 备注 |
| --- | --- | --- |
| macOS | `CGEventCreateScrollWheelEvent` + `CGEventPost(.cghidEventTap)` | 需要辅助功能权限；单位设为像素 |
| Windows | `SendInput` + `MOUSEEVENTF_WHEEL` | `WHEEL_DELTA=120`，每次 3–6 格 |
| Linux X11 | `XTestFakeButtonEvent` button 4/5 | 每格 3 行 |

步长策略：

```
step_px = clamp(viewport_h * step_ratio, 0.3 * viewport_h, 0.85 * viewport_h)
step_ratio 默认 0.7
重叠量 = viewport_h - step_px  ≥ min_overlap（默认 48px）
```

为什么不是「一屏一屏」：重叠太少时匹配没有冗余，一次失配就整段错位。0.7 屏意味着
30% 重叠，既够匹配，又不会让帧数翻倍。

**惯性滚动**（macOS 触控板、Windows Precision Touchpad 合成事件）会导致抓帧时还在动 →
所以抓到帧之后必须做**稳定检测**。

## 6. 稳定检测（抓帧时机）

一帧「可用」的条件（全部满足）：

1. 与上一帧的整幅平均绝对差 `< 1.0`（画面静止）；
2. 距离滚动事件至少 `settle_ms`（默认 120 ms，给 CSS 动画和懒加载留时间）；
3. 连续满足 1、2 的帧数 ≥ 2（避免内容先淡入后位移）。

超时（默认 800 ms）仍不稳定 → 用当前帧继续，但在日志里记 `unstable_frame`，
并在最终置信度上打折。

## 7. 位移估计

设上一帧 `P`、当前帧 `N`，均为 `H × W`（物理像素），先把固定行/列剔掉，得到
内容区 `[top, H-bottom)`、高度 `h`，以及**运动列掩码** `M`。

### 7.1 固定行检测（粘性页眉 / 页脚）

粘性元素不随内容移动，因此它在两帧中的**同一 y 位置**内容相同：

```
row_diff(y) = mean_x |P[y][x] - N[y][x]|
```

从顶部向下扫描，连续满足 `row_diff ≤ fixed_row_threshold`（默认 6）的行记为 `top`；
从底部向上同理得 `bottom`。两者都限制在 `H/3` 以内（否则说明整页没动）。

这两段行**不参与匹配**，合成时也只保留第一次出现的页眉，页脚直接丢弃。
（丢弃页脚是刻意的：它通常是工具栏/状态栏，不属于内容。）

### 7.2 运动列掩码（固定侧边栏）

同理，固定侧栏在**同一 x** 上内容不变：

```
col_diff(x) = mean_y |P[y][x] - N[y][x]|      // 只统计内容区
```

`col_diff ≤ motion_column_threshold`（默认 4）的列 → 静态列，从匹配中剔除。
若有效列占比 `< 15%`，判定「画面几乎没变」→ 结束。

这一步是质量分水岭：不剔除固定侧栏时，宽 60px 的悬浮按钮会让整幅相关性虚高，
导致错误的 `d` 也能拿高分。

### 7.3 相关函数

用 **零均值归一化互相关（ZNCC）**，不用 SAD：

```
          Σ (a_i - ā)(b_i - b̄)
ZNCC = ─────────────────────────────
        sqrt(Σ(a_i-ā)² · Σ(b_i-b̄)²)
```

- 对整体亮度漂移（+10%）和对比度变化免疫 —— SAD 会因此偏移 1–3 px；
- 值域 `[-1, 1]`，`1` 为完全一致，可作统一置信度阈值；
- 在掩码列上计算，代价与有效内容成正比。

位移定义：`d` 表示「上一帧第 `y+d` 行 == 当前帧第 `y` 行」，即页面向上滚了 `d` 像素。

```
score(d) = ZNCC( P[top+d .. top+d+overlap], N[top .. top+overlap] , M )
overlap  = h - d
d ∈ [0, h - min_overlap]        // d = 0 即「没有滚动」，用于到底检测
```

### 7.4 由粗到精（金字塔）

```
levels = [4, 2, 1]        （内容区 < 256 px 退化为 [2, 1]，< 128 px 退化为 [1]）

level 4：两帧各做 4× 盒式降采样 → 全范围扫描（步长 1，等效 4 px）
level 2：在上一级结果 ±4 px 内精扫
level 1：在上一级结果 ±2 px 内全分辨率精扫（行采样步长 2）
```

为什么封顶在 4×：盒式降采样会把文字笔画、1 px 边框这类高频内容平均成一片灰，
**8× 那一层恰好把相关性赖以存在的信号抹掉了**。原型实测：8× 首层给出一个错误的
中位，后两级无法挽回（1440×900 视口下估出 752 而非 630）。4× 仍保留 8 倍的计算量
削减，且内容还能辨认。

粗层还会把参与相关的列限制在 ~128 条（`stride = ceil(cols / 128)`）：统计不需要每
一个像素列，代价因此只与内容区大小成正比，与窗口宽度无关。

原型（`crates/pinshot-stitch`）已实现该金字塔，实测见 §7.6。

### 7.5 多列带投票（可选增强）

把内容区横向切成 5 条带，各自独立估计 `d`，取中位数；若某条带偏离中位数 > 8 px，
标记该区域为「不可信」（通常是动画广告或视频）。P1 阶段实现。

### 7.6 原型实测

`cargo run --release --example bench -p pinshot-stitch`：1440×900 视口、64 px 粘性页眉、
步长 630 px、18 次滚动、页面高 12000 px。

| 指标 | 实测 | 预算 |
| --- | --- | --- |
| 单帧对位移估计 | 9.2 ms | ≤ 12 ms |
| 整页（18 对）拼接 | 166 ms | ≤ 400 ms |
| 位移误差 | 0 px（全部 18 对） | ≤ 1 px |
| 拼接高度 | 12064 = 64 页眉 + 12000 | 相等 |

同一份代码在 360×300 的小帧上走全分辨率路径，10 个单元测试合计 0.17 s。

## 8. 合成

```
输出 = 第一帧的页眉行
     + 第一帧的内容区
     + Σ (每帧内容区的最后 d 行)
```

重采样：平移只做整数像素拷贝，**不做插值**（插值会让文字发虚）。
仅在最后因缩放比不一致需要重采样时才用 Lanczos3。

接缝处理：
- 默认**硬接缝**：直接把新行贴上去。因为相邻帧内容逐像素相同，硬接缝是无缝的；
- 若 `score` 在 `[0.80, 0.85)`，说明可能有 1px 错位 → 用 3 行 feather 混合，
  并在 `scroll:seam_warning` 里标记位置；
- `score < 0.80` → 不合成，回溯一帧重抓（最多 3 次）。

高度保护：`max_height`（默认 20000 px）或内存 512 MB 触顶时停止，
长图尾部追加一条 8px 的截断提示条（仅预览，导出前可用选项关闭）。

## 9. 停止条件

| 条件 | 判定 | 结果 |
| --- | --- | --- |
| 到底 | 连续 2 帧整幅差异 < 1.0 | `EndOfContent` |
| 无重叠 | 最优 `d > h - min_overlap` | `NoOverlap`（提示可能滚太快） |
| 触顶 | 累计高度 ≥ max_height | `MaxHeight` |
| 帧数上限 | ≥ 200 帧 | `MaxFrames` |
| 用户取消 | Esc / 关闭 | `Cancelled`（保留已拼部分） |
| 置信度低 | 3 次重试仍 < 0.85 | `LowConfidence`（转手动） |

## 10. 边界情况与对策

| 情况 | 现象 | 对策 |
| --- | --- | --- |
| 粘性页眉 | 长图顶部重复出现导航 | 固定行检测，只保留一次 |
| 固定侧栏 / 客服气泡 | 位移估计偏移 | 运动列掩码 |
| 懒加载 | 长图有空白块 | 稳定检测要求连续 2 帧一致 + 120 ms |
| 视频 / GIF | 相关性骤降 | 灰度 + 模糊 + 列带投票中位数 |
| 平滑滚动 | 抓帧时还在动 | settle 窗口 + 超时降级 |
| 视差背景 | 前后景位移不同 | 列带投票取中位数，前景优先 |
| 吸底工具栏 | 底部固定条重复 | 固定行检测，丢弃页脚 |
| 无限滚动列表 | 永远滚不完 | `max_height` + `max_frames` |
| 页面缩放 ≠ 100% | 抓到的帧已被系统缩放 | 记录 `device_scale`，导出按比例；不做亚像素匹配 |
| 滚动事件被拦 | 画面不动 | 连续 2 帧无位移即降级为手动模式 |
| 深色模式切换 | 整幅亮度突变 | ZNCC 免疫 |

## 11. 降级路径（必须有）

1. `LowConfidence` → 弹一条非模态提示，按钮：**「改用手动滚动」** / **「保留原始帧」**。
2. 手动模式：用户滚动，程序只负责抓帧与拼接，拼接失败就继续抓，最终在长图上标出可疑段。
3. 全失败：把 `frames/` 目录路径给用户（`~/Library/Caches/PinShot/scroll/<job>/`），
   告知可以用「导入帧序列」重试 —— 这条路径同时是我们的排障入口。

**绝不静默产出错位长图。** 宁可少拼一屏，也不能给用户一张接缝错开的图。

## 12. 质量指标与基准

基准集：20 个真实页面（GitHub issue/PR、知乎回答、微信公众号、Notion 文档、
长表格、无限滚动列表、懒加载图库、深色模式、带视频、带粘性侧栏……），
脚本化录制，人工标注期望高度与关键行。

| 指标 | 目标 |
| --- | --- |
| 自动模式成功率 | ≥ 80%（16/20） |
| 含手动降级后的总成功率 | ≥ 95% |
| 位移估计误差 | ≤ 1 px（100% 的帧） |
| 接缝可见错误 | 0（无未标记的错位） |
| 单页耗时（1000 px 高） | ≤ 1.6 s |
| 长图体积（PNG，宽 1440） | ≤ 1.2 MB / 1000 px |

## 13. 可测试性

拼接是纯函数：

```rust
pub fn stitch(frames: &[Gray], opts: &StitchOptions) -> Result<Stitched, StitchError>
```

- **合成帧测试**：程序生成「已知页面 + 已知滚动偏移 + 粘性页眉 + 固定侧栏 + 噪声」，
  断言拼出的长图与原始页面逐像素相等。已在 `crates/pinshot-stitch/tests/stitch.rs` 实现。
- **真实帧测试**：`pinshot scroll --frames <dir> --json` 可对任意帧序列重跑算法，
  线上问题可复现、可回归。
- **属性测试**（P1）：随机生成页面与滚动序列，断言「拼出高度 = 页面高度」恒成立。
