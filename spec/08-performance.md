# 08 · 性能预算

> 原则：**截图工具的性能问题不是"慢"，是"打断了手"。** 超过 100 ms 的停顿会被感知为
> "卡了一下"，而每次截图都卡一下就没人用了。所以预算按"人能否察觉"来定，不按硬件定。

## 1. 硬预算

| 动作 | 预算（p95） | 依据 |
| --- | --- | --- |
| 全局热键 → 覆盖层首帧可见 | 100 ms | 低于此值感觉是"立即" |
| 拖框跟随光标 | 16 ms（60 fps） | 单帧 |
| 标注笔迹 | 16 ms | 单帧，5K 全屏底图 |
| 放大镜更新 | 8 ms | 跟随鼠标，晚一帧就"打滑" |
| 选区内复制到剪贴板 | 60 ms | PNG 编码 + 剪贴板写入 |
| 保存到文件（5K PNG） | 250 ms | 含 fsync |
| 贴图从剪贴板出现 | 120 ms | 4K 图 |
| 滚动单帧位移估计 | 12 ms | 见 §3 |
| 滚动任务完成（12000 px 页面） | 400 ms 计算 + 抓帧 | 见 §3 |
| 历史面板首屏（1000 条） | 80 ms | 缩略图懒加载 |
| 常驻内存 | 60 MB | 无贴图时 |
| 20 张 4K 贴图 | 300 MB | LRU + 缩略图 |

## 2. 冷启动

| 阶段 | 预算 |
| --- | --- |
| 进程启动 → 托盘图标出现 | 400 ms |
| 首次 `session_start`（含 SCK 冷启动） | 250 ms |
| 后续 `session_start`（stream 已热） | 60 ms |

冷启动慢的主因是 `SCShareableContent` 枚举窗口（100–200 ms）。做法：
启动后异步预热一次，把结果缓存 500 ms；用户按热键时先展示"正在抓屏"的空覆盖层
（有边框反馈，不是黑屏），抓到再换图。

## 3. 滚动拼接实测（已实现）

`crates/pinshot-stitch`，release 构建，Apple Silicon：

```
cargo run --release --example bench -p pinshot-stitch

viewport        1440×900
frames          19
page height     12000
stitched height 12064
per pair        9.23 ms
total           166.1 ms
offsets         [630 × 18, 454]
```

| 指标 | 实测 | 预算 | 结论 |
| --- | --- | --- | --- |
| 单帧对位移估计 | 9.2 ms | 12 ms | ✅ |
| 18 对总计 | 166 ms | 400 ms | ✅ |
| 位移误差 | 0 px | ≤ 1 px | ✅ |
| 内存（19 帧 × 1440×900×1B） | 25 MB | — | 灰度帧，不含 RGBA |

两个优化来自实测，已经写进代码注释：

1. **金字塔封顶 4×**。8× 那一层会把文字笔画平均成一片灰，相关性失去信号，
   实测给出错误位移（752 而非 630），而且后两级无法挽回。
2. **粗层列抽样到 ~128 列**。相关性是统计量，不需要每一个像素列；
   代价因此与内容区大小成正比，而不是与窗口宽度成正比。

未做完整全分辨率扫描的代价：1440×900 下单帧对约 64 ms，10 屏就是 1.1 s —— 不可接受，
所以金字塔是必需项，不是优化项。

## 4. 内存模型

| 对象 | 大小 | 生命周期 |
| --- | --- | --- |
| 冻帧（RGBA，5K） | 59 MB | 覆盖层存在期间；退出即释放 |
| 覆盖层 canvas | 59 MB（GPU 纹理） | 同上 |
| 标注场景 | < 1 MB | 同上 |
| 贴图缩略图 | ≤ 1.4 MB / 张 | 常驻 |
| 贴图原图解码 | 33 MB / 张（4K） | 可见时，LRU 淘汰 |
| 滚动帧（灰度） | 1.3 MB / 帧 | 任务期间 |

不做的事：

- 不缓存"最近 N 张截图"的解码位图（那是 59 MB × N）。
- 不在 UI 线程解码任何图片。

## 5. 测量方法（可复现）

内置基准命令，输出 JSON，可直接进 CI：

```bash
pinshot bench overlay        # 热键 → 覆盖层可见，100 次
pinshot bench annotate       # 每种形状 1000 次笔迹，报告 p50/p95
pinshot bench export --size 5120x2880
pinshot bench scroll --frames ./fixtures/scroll/github-issue
```

`bench scroll` 直接复用 `pinshot-stitch`，与 `--example bench` 同源但可喂真实帧目录。
CI 里只跑 `scroll` 与 `annotate`（不需要屏幕），其余手动或在本机 nightly 跑。

## 6. 回归门禁

`spec/09-plan.md` 的每个里程碑都要跑一次 `pinshot bench`，若任一 p95 超出预算 20%，
该里程碑不算完成。性能预算和功能验收同等地位。
